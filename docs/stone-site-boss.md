# 石址守望者：模型兼容性与首领配置

用户提供的 `runestone-warden-golem.bbmodel` 可用于当前 BetterModel 首领方案。已验证的是模型转换及隔离服务端运行；客户端观感、帧率和 Folia 实际运行仍需验收。

## 模型兼容性

| 检查项 | 结果与边界 |
| --- | --- |
| 原始格式 | Blockbench Generic/free，不能直接当作原版 Java 实体模型安装；由 BetterModel 转换 |
| 几何与纹理 | 297 个立方体、31 根骨骼、256×256 内嵌纹理；原文件未修改，几何与 UV 保留 |
| 多轴旋转 | 24 个立方体有多轴旋转；BetterModel 已生成包含固定显示旋转的子模型，没有因原版单轴限制丢失几何 |
| 生成结果 | 68 个子模型，共 297 个立方体；31 根骨骼被真实 EntityTracker 加载 |
| 原有动画 | idle、walk、attack_1、attack_2、special、death，共 12,180 个关键帧 |
| 补充内容 | 通过 Blockbench MCP 增加 spawn、hurt；独立 wave 模型提供地面预警与冲击效果 |
| 当前测试组合 | Leaf/Purpur 26.3、Java 25、BetterModel 3.6.0-SNAPSHOT-534、MythicMobs 5.14.0-SNAPSHOT-local、CraftEngine 26.9.2 |
| 客户端资源 | 真实 BetterModel build.zip 已生成，pack_format=97；客户端仍需接受 CraftEngine 合并后的整包 |
| 碰撞与命中 | 底层铁傀儡缩放 1.4；外观独立缩放 1.05，约 3.8 格高。肩甲、手臂和藤蔓没有逐块命中箱；攻击由配置中的范围及玩家实际位置判定 |
| 发光 | 青色纹理属于模型颜色，不保证原版客户端自发光，也不提供真实动态光源 |
| 性能 | 当前仅生成一只公共首领；不能将本次无客户端测试解释为多人 FPS/TPS 压测通过 |

原模型与导出模型的对比、真实生成包的统计可用 `tools/analyze_boss_model.py` 重现，报告在 `target/boss-compatibility.json`。Blockbench 预览位于 `assets/stone-site-warden/preview.png`，该预览不等同于 Minecraft 截图。

## 默认战斗规则

- 地图为常驻 `lost_altar`，首领位置 `-28.5 31.0 -129.5`，为用户截图紫色符文圆台中心。地板 Y=30、脚部 Y=31，活动半径 16 格；不改动地图方块。
- 基础生命 1000，个人贡献门槛为 50 点实际扣血。若配置超过服务端生效的生命属性上限，会拒绝召唤并记录原因。
- 首次等待 180 秒；击杀或异常结束后等待 1500 秒。时间保存至 SQLite，重启保留；刷新需要副本内有可战斗玩家且其位于安全区外。
- 追击半径 16 格，场地附近持续 60 秒没有可战斗玩家则回位、回满血并清除本轮贡献。
- 普攻、横扫、范围技能使用用户模型原有动画；伤害时刻、范围及数值在 `boss.yml` 配置。
- 地面预警、冲击波、出生和死亡动画均由 BetterModel 加载。视觉资源异常时中止战斗，依赖缺失或停用只暂停首领，不停用整个副本。
- 普通怪与精英怪的已有刷新和材料掉落保持原规则。

## 个人奖励

每位玩家独立判断资格及抽奖：

1. 贡献达到基础最大生命 5%；只累计确认发生的生命减少，不把取消、免疫或溢出部分计入贡献。
2. 最近 60 秒有有效伤害。无法确认玩家来源的伤害不计贡献。
3. 击杀结算时在线、拥有 `dungeon.use`、同世界且距死亡位置不超过 64 格。死亡不清贡献，脱战重置会清除。

每位合格玩家获得一份绑定本人的「守望者战利品」。主手右键开启后，至少获得一件石址材料，并有 15% 概率额外获得星芽短剑。抽到剑后，普通占 80%，优秀占 17%，稀有及以上合计占 3%，组内品质遵循 AsterStats 的相对权重。礼包材料池和短剑概率由 `plugins/Dungeon/boss-spoils.yml` 控制。

材料幸运方块默认 25%。生成器幸运方块独立判定，默认 3%，仅每日前 3 次合格击杀参与，每天最多获得 1 个。幸运方块的抽取和限额按击杀当天结算，开包时取出对应物品。日界按 Asia/Shanghai，待领取奖励也占获奖额度。

SQLite 先保存开包抽取计划，再保存生成后的短剑和奖励清单。两步均按礼包收据绑定玩家。成功入库后消耗实体礼包，背包满时使用 `/dungeon rewards` 继续领取。旧版待领奖励可以通过同一命令继续领取。

没有尾刀奖或排名奖。战斗 ID 与玩家 UUID 共同去重，奖励记录和每日额度在同一 SQLite 事务提交。

满包奖励保留，使用 `/dungeon rewards` 领取。物品带唯一收据；重启发现交付中断的记录会进入 REVIEW，找到背包或末影箱中的对应收据后可确认，否则保留给管理员核对，不自动重复发奖。

SQLite 与 Minecraft 玩家库存不能跨系统原子提交。突然断电发生在数据库已确认、玩家数据尚未保存的窗口时仍可能丢失物品；本实现不承诺硬崩溃下绝对零丢失。核对不确定记录前应备份 `plugins/Dungeon/boss-rewards.db` 及其 WAL 文件，并保存相关玩家数据。

## 文件、命令与部署

| 路径或命令 | 用途 |
| --- | --- |
| `plugins/Dungeon/dungeons/lost_altar/boss.yml` | 战斗、刷新与个人奖励配置，schema-version=1 |
| `plugins/Dungeon/boss-hologram.yml` | 刷新点全息字开关、高度、可见距离、字号与换行宽度 |
| `plugins/Dungeon/lang/zh_CN.yml` | 统一中文文案，首领与奖励反馈位于 `boss` |
| `plugins/Dungeon/boss-spoils.yml` | 战利品材料池与短剑抽取概率 |
| `plugins/CraftEngine/resources/dungeon_spoils` | 礼包的客户端模型和 32×32 贴图，源文件在 `deploy/warden-spoils` |
| `plugins/Dungeon/boss-rewards.db` | 击杀、额度、领取与下次刷新时间 |
| `plugins/MythicMobs/mobs/DungeonStoneSiteWarden.yml` | 底层 MM 首领定义，无固定刷怪点 |
| `plugins/BetterModel/models/dungeon/stone_site_warden.bbmodel` | 基于用户模型的首领 |
| `plugins/BetterModel/models/dungeon/stone_site_wave.bbmodel` | 预警与冲击视觉资源 |
| `/dungeon rewards` | 普通权限 `dungeon.use`，领取待领奖励 |

首次启动新版时，原来的五份中文文件会合并为 schema 2 的 `lang/zh_CN.yml`。原文件备份在 `plugins/Dungeon/backups/language-v2`。缺少的文案键从插件内置默认值读取，也可以在对应分组下自行补写。
| `/dungeon boss status` | 管理权限 `dungeon.admin`，查看首领状态 |
| `/dungeon boss spawn` | 管理权限 `dungeon.admin`，立即召唤；同样执行真实战斗和发奖 |

插件仅补齐缺失的默认文件，不覆盖管理员配置和模型。首次部署需在正常启动前放好两个模型及 MM 定义，避免依赖先加载、资源随后才安装而需要再次启动。

当前 leaf 的 CraftEngine 已配置合并 `BetterModel/build.zip`。正常启动生成 BetterModel 包后，需要重新构建并向玩家分发 CraftEngine 整包；不要用隔离测试服的 build.zip 覆盖正式服，否则会丢掉正式服其他模型资源。上传 JAR 与资源不代表运行中已生效，不使用热加载或全服 `/reload`。

`boss.yml` 在常驻副本启动时读取。现有 `/dungeon reload` 只负责阶段副本定义，不会热重建本首领模块；更改首领配置、模型或依赖后使用正常重启。

## 刷新点全息字

使用原生 TextDisplay，无需额外全息字插件或专用资源包。默认贴近圆台地面 `-28.5 31.35 -129.5`（脚部上方 0.35 格），64 格范围可见、缩放 0.9、透明背景及文字阴影，不透过墙体显示。文案位于 `lang/zh_CN.yml` 的 `boss.hologram` 节点，只显示两行：首领名称，以及刷新倒计时（首领存在时显示简短状态）。不展示技能、掉落和奖励条件。

每秒显示真实模块状态；死亡后使用 SQLite 刷新计划恢复的同一个截止时间倒计时，向上取整到秒，不维护第二套计时。截止但没有合适玩家时显示 `00:00`；首领存在时改为已刷新、战斗中或回位中；依赖/存储不可用时不显示伪倒计时。全息字固定在刷新点，不跟随首领移动。

首领成功刷新后，向当前副本内玩家发送一次 Title 和聊天通知。标题为“石址守望者”，副标题为“已在石址苏醒 · 前往圆台挑战”；淡入 0.4 秒、停留 3 秒、淡出 0.6 秒，文案可在 `lang/zh_CN.yml` 的 `spawn-title`、`spawn-subtitle` 和 `spawned` 修改。发送在玩家所有权线程检查在线、世界、权限及本轮身份；离线、切世界或模块已关闭时取消。

死亡保留原来的 BetterModel EntityTracker 与查看者，不先关闭模型再创建死亡替身。普通受击使用 BetterModel 原生短暂红闪；致死时终止其他动作、取消染红计时并在渲染队列恢复原色，原模型仅执行一次死亡动作；已有 BetterModel 内建死亡动画直接复用，动画完成或兜底期限到达后释放。玫瑰精英的自定义枯萎动作采用同一清理路径，MM 死亡事件和掉落仍正常执行。

没有附近玩家时不为全息字强制加载区块，不持常驻票据。创建和更新位于位置所属区域；实体不保存至地图，区块卸载释放引用，关闭取消定时任务并按所有权回收，标记只用于清理本插件遗留显示实体。Paper 关闭路径已测试；Folia 禁用时若显示不归当前线程且插件已禁止调度，则依赖不持久化、区块卸载和下次加载标记恢复，禁止跨区强删，仍需 Folia 实机验收。

## 线程与验证范围

数据库串行异步执行；区块异步加载；实体操作回到实体所有权线程。地面效果的中心可能跨越首领所在区域，因此按效果位置调度；玩家伤害和库存交付回到各玩家自己的调度器，并重新检查状态及位置。

Paper 路径仅为 3×3 场地区块持有临时票据，结束后释放；不卸载或删除常驻世界。Folia 检测到区域线程后不持长期票据，实体所属区域卸载而退休时中止本轮，不发奖励，按正常间隔再次刷新。这是明确的保守降级；本轮没有 Folia/Canvas/Arbor 实机运行证据。

已执行 Maven 构建、贡献/奖励存储测试，以及 `tools/verify_boss.py` 隔离服务端检查：真实 MM 召唤、重复召唤保护、BM 挂载、动画管线与效果、实际移动物理、受伤、死亡和效果清理、区块票据释放、依赖停止时迟到召唤取消。动画管线使用无查看者下的公开 API 求值，不冒充真实客户端显示测试。真实多人攻击命中、库存联机流程、客户端帧率与长时间压力测试尚未完成。

## 模型归属与受击反馈

MM 的 `DungeonStoneSiteWarden.yml` 使用 `bm:model` 出生技能创建模型，Dungeon 从 BetterModel 注册表取得同一个 `stone_site_warden` tracker，不再重新挂载。MM 出生技能可能延迟执行，Dungeon 在实体所有权调度器最多等待 40 tick；期间无敌，失败清理实体并记录具体配置提示，依赖停止和插件关闭取消等待。

`/mm mobs spawn 石址守望者` 会加载模型；手动召唤不属于公共战斗，不获得 Dungeon 技能、个人奖励与通知。公共首领仍使用 `/dungeon boss spawn` 或自动刷新。既有安装需要合并新版 MM 出生技能；只替换 JAR 不会覆盖管理员的 MM 文件。

普通受击红闪由 BetterModel 管理，Dungeon 不额外播放重叠的自动受伤动作。首领 `boss.yml` 的 `impact` 默认抗性 0.75，冲量上限水平 0.16、向上 0.12 格/tick，保留 6 tick 不让移动逻辑覆盖；不额外制造击退。施法、出生、回位和终态取消击退。玫瑰精英保持扎根，不改变其位移规则；普通受击红闪一并恢复。

该迁移不改变模型几何，之前静止散开问题不在此修复范围。
