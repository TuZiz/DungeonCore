# 副本大厅建议（设计稿，尚未实现）

建议主题：冒险者公会 + 传送门广场。先做一个紧凑常驻大厅，中心集结，左右副本入口，后方返回主城；新玩家出生朝向入口说明，减少寻找入口的时间。建筑可用石砖、深板岩、木梁与少量青色光源，方便后续接遗迹、矿坑、地下城等入口。

## 最小玩法流程

进入大厅 -> 查看副本介绍/人数/难度 -> 组队 -> 队长选择副本与难度 -> 校验全部成员状态 -> 传送开局 -> 通关/失败/退出 -> 回到大厅安全出生点。

大厅只负责集结和入场，不承载战斗进度，不参与临时实例清理。各入口可先用固定方块交互，后续再按需要增加 NPC 或 GUI；当前没有实现这些大厅入口。

## 建议分区

- 中央：安全出生点、简洁操作说明与队伍集结区。
- 前方：副本入口，每个入口给出名称、人数和推荐难度。
- 两侧：队伍等候区与尚未开放入口的装饰预留，第一版不实现额外系统。
- 后方：返回主城入口。

## 技术实施边界

大厅放在已加载的独立常驻世界最清楚；若当前多世界能力不足，可先在现有世界划定区域。两者都不需要为每次挑战复制大厅。

下一阶段实现时将大厅点位放入独立 lobby.yml（schema-version、世界、出生坐标及区域边界），不堆进 config.yml。提供玩家 /dungeon lobby 与管理 setlobby 入口，普通权限仍使用 dungeon.use。设置与保存异步执行，玩家操作走实体调度器，区域保护仅覆盖大厅边界。

建议保护大厅内 PvP/怪物伤害、刷怪、破坏与放置；须实际实现监听后才能称为安全区。统一返回大厅应采用 lobby/原进入点的明确返回策略；当前代码仍返回进入前位置，尚未实现统一回大厅。副本进行中不得通过大厅入口绕过退出流程。

当前尚未建设大厅地图，也没有增加 lobby.yml、GUI 或大厅命令。需要实际开发时按上述最小流程实现，建筑尺寸和具体点位以使用中的地图为准。
